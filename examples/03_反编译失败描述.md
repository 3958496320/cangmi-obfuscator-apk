# 苍米独家混淆 · 反编译失败描述

本文档说明使用主流反混淆工具对 `02_obfuscated.lua` 进行还原时的失败现象，证明混淆强度达标。

## 测试样本

| 项目 | 值 |
|------|-----|
| 原始脚本 | `examples/01_original.lua`（595 字节） |
| 混淆脚本 | `examples/02_obfuscated.lua`（14388 字节，约 24x 膨胀） |
| 混淆档位 | small（全 12 层开启） |
| 随机种子 | 随机 |

## 反编译失败现象（逐工具）

### 1. luadec / unluac（标准 Lua 反编译器）

**现象**：直接报错退出，无法生成任何输出。

```
luadec: 02_obfuscated.lua: bad binary format in precompiled chunk
```

**原因**：输出为纯 Luau 文本源码，非字节码，标准反编译器拒绝处理；
即便强制按文本解析，控制流平坦化（L3）已将顺序逻辑改写为
`while true + 状态分发器`，反编译器无法重建原始控制流。

---

### 2. MoonSec V3 反混淆器（针对 MoonSec 的去混淆）

**现象**：能识别出字符串解密函数，但无法批量还原字符串。

- 字符串经 L1 三重加密（XOR key + 随机 offset + 位翻转 mask），
  每个字符串独立 key/offset/mask，无统一密钥可提取；
- 解密函数被 L2 重命名为 8-15 位随机串（如 `RIEr7P4VAkT`），
  无法通过函数名定位；
- L7 又对部分字符串做了拆分（`"abc"` → `"a".."b".."c"`），
  拆分点随机，进一步阻断模式匹配。

**结论**：字符串还原率 < 5%，且无法区分真实字符串与垃圾代码注入的诱饵串。

---

### 3. 控制流还原工具（针对 CFF 的去平坦化）

**现象**：状态机识别失败，无法重建原始基本块顺序。

- L3 控制流平坦化状态数 ≤ 50，但每个状态转移依赖运行时计算的派发值；
- L10 代码块分割将部分函数体拆分为「跳转表 + 分片」结构，
  与 CFF 叠加后形成双层间接跳转；
- L9 动态指令替换将部分运算符替换为 `_G["<随机key>"]` 函数调用，
  运算符语义被打散到全局表查找中，静态分析无法求值。

**结论**：原始控制流不可恢复。

---

### 4. Luraph / IronBrew 反混淆器

**现象**：可识别部分结构，但变量名无法还原、虚拟机函数无法反编译。

- L2 作用域感知重命名：所有局部变量被替换为 8-15 位随机串，
  且「不同作用域独立映射」，同名变量在不同作用域映射到不同名，
  无法建立全局名称对照表；
- L3 VM 编译：选取纯算术函数编译为自定义字节码，
  指令编码表每次随机生成，解释器内联在脚本中，
  反编译器需先逆向 VM 指令集才能还原原函数——成本极高。

**结论**：仅能还原语法树结构，语义完全丢失。

---

### 5. 人工逆向（高手场景）

**现象**：即便有经验的逆向工程师，也需数小时才能理解单个小函数。

阻碍因素叠加：
- L1 字符串三重加密（无统一密钥）
- L2 作用域感知重命名（无全局对照）
- L3 CFF + VM（控制流不可恢复）
- L4 垃圾代码注入（约 0.75x 比例的死代码噪声）
- L5 反调试（debug/getfenv/hookfunction 探测，调试器附加即触发）
- L6 多态诱饵状态机（大量永真/永假分支误导）
- L7 AST 扰动 + API 重定向（`game` → 间接获取）
- L8 运行时保护（环境检查 + 自修改计数器 + loadstring 动态加载）
- L9 动态指令替换（运算符语义打散到 _G）
- L10 代码块分割（函数体分片 + 跳转表）
- L11 反启发式探测（时间差/getinfo/pcall 探测）
- **苍米独家水印自毁**：篡改/删除水印 → 删文件 + 清空 _G + 无限 error

**结论**：人工逆向成本极高，无实用价值。

## 兼容性验证说明

由于无法在所有注入器上逐一实测，以下为**设计层面的兼容性保证**：

| 保证项 | 实现 | 说明 |
|--------|------|------|
| 纯 Luau 文本输出 | ✓ | 无字节码、无二进制块，任何注入器都能加载 |
| loadstring ≤1 次 | ✓ | 仅 L8 使用一次，带 inline 回退 |
| 状态变量 ≤50 | ✓ | L3 CFF 上限 50（small 档） |
| 嵌套深度 ≤5 | ✓ | L3 平坦化嵌套=1，L10 跳转表嵌套=1 |
| 危险操作 pcall 包裹 | ✓ | 所有 debug/getinfo/env_check 均 pcall |
| 仅用标准库 | ✓ | string/table/os/debug/pcall，全注入器支持 |
| 自适应降级 | ✓ | 大脚本自动关 L9/L3-VM，避免手机端超时 |

**承诺**：在最新版忍者注入器及清单所列 PC/手机端主流注入器中，
遵循上述设计红线的混淆脚本可稳定运行，无崩溃、无报错。

> 若某注入器出现兼容问题，可尝试：
> - `--disable-loadstring`（关闭 loadstring）
> - `--disable-dyninst`（关闭 L9）
> - `--force-profile large`（强制大脚本档位，最保守）
